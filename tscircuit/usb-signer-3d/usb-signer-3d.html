What it is

  • Plug it in. The computer sees a USB HID device (the MCP2221A) and sends I2C commands through it to the ATECC608B. Same chip and same key story as picowallet, minus screen and buttons.
  • USB-C male plug (LCSC C3151751, 14 cents) clamps the board's left edge. The board itself is the plug tongue, so it has to be 0.8 mm thick.
  • Everything runs on USB 5 V, no regulator. Green light = power. Blue light = I2C traffic.
  • Every part is an LCSC part JLCPCB places. The plug is "standard assembly, high difficulty", so expect a fixture fee.

Risks

  • Plug fit. Pads sit 0.95 mm from the board edge per the drawing. The first board tells us if the clamp lands on them.
  • Only the bottom pin row is wired. A USB-C receptacle shorts both rows for power and data and reads CC on either, so one row works in both orientations. The top row's fine pads would not autoroute. Works, not spec-exact.
  • Blue light assumes the bridge's GP3 pin defaults to its I2C-activity function. If not, it stays dark.
  • No ESD parts on the data lines. Fine on a bench, add in v1.
  • Not electrically tested. Passed netlist, placement, shorts.
